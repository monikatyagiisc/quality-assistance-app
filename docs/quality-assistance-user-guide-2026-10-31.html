Overview

What this application does

Quality Assistance is an AI-powered helper for software quality engineering. You provide context about a feature or change; the application sends that context to its configured AI service, where specialized assistants generate suggestions and analysis.

Plan tests

Turn requirements and user stories into test scenarios, priorities, and coverage ideas.

Explore test data

Suggest normal, boundary, invalid, and other useful data values for test scenarios.

Plan automation

Get automation approaches, script outlines, and ideas for handling changed selectors.

Analyze changes and failures

Review code diffs or test-run logs for possible impact, defects, and follow-up checks.

Summarize quality

Create test summaries and release-readiness considerations for people to review.

Important: The application generates AI suggestions; it does not run your product’s test suite or make a release decision. Review and verify every result with your team and your actual system.

Preparation

Before you start

  • Use a supported, up-to-date web browser and the application URL provided by your team.
  • Have a short feature description, acceptance criteria, or test evidence ready. You can start with one of the built-in samples instead.
  • Account creation and sign-in must be enabled by the application administrator.
  • Jira, Microsoft SSO, and GitHub are optional integrations. They appear only after an administrator configures the corresponding integration for this deployment.
  • Use only information that your organization permits you to share with this application and its configured AI provider.

If you are new to the tool, you can skip integrations and use a sample or enter a requirement manually.

Step 1

Create your account and sign in

  1. Open the application and choose Get started or Create an account.
  2. Enter your name, work email, and a password that meets the form’s minimum length.
  3. Choose Create account. After registration, the app opens your workspace.

If your organization has enabled Microsoft Entra ID, you can use Sign in with Microsoft. Existing app accounts may need to sign in once with their current method and link the same-email Microsoft account in Settings first. Otherwise, use your app email and password. Select Sign out from your profile menu when you finish on a shared device.

Step 2

Run your first quality review

  1. Open Workspace. The workspace has separate Input and Results tabs.
  2. For an easy first try, select a sample card such as Smoke test orFull E2E demo. The sample fills in the form; it does not run until you submit.
  3. Or type your own feature description in Software requirements. Include what should happen, who uses the feature, important rules, and acceptance criteria.
  4. Optionally add a user story or code change. See Understand the input fields.
  5. Choose Get quality assistance. The Results tab opens and shows progress while the assistant works.
  6. Read the response, check assumptions, and refine your input or ask a follow-up if needed.
Tip: More context usually gives more relevant suggestions. State constraints explicitly—for example supported browsers, roles, data rules, error behavior, or out-of-scope areas.

Built-in sample requests

  • Smoke test: a small example for trying requirement analysis.
  • Full E2E demo: a sample with requirements, user stories, and a sample code diff.
  • Change impact: an example focused on reviewing a code change.
  • Execution & reporting: sample test-run results to analyze and summarize.
  • Automation & self-healing: example automation context and selector changes.
  • Follow-up (same session): a refinement request that uses an earlier response in the current session.

Samples are starting points, not fixed tests. After loading a sample, edit any field to fit your scenario. Choose Clear to clear the current inputs and result.

Optional integration

Use Jira to import a story

When Jira Cloud OAuth has been configured, you can connect your own Atlassian account and load issues assigned to you. The issue picker imports a story’s key, title, and description into the user-story field.

  1. Open your profile menu and choose Settings.
  2. Under Jira Cloud, choose Connect Jira.
  3. Sign in to Atlassian with the account that can access your company Jira site and approve the requested access.
  4. Return to Workspace → Input, then choose Load my issues.
  5. Select an issue from the dropdown. Review its preview; the title and description are copied into User stories.
  6. Review or edit the imported text before submitting. Use Load more issues if the issue is not on the first page.

The issue must be assigned to the Jira account you authorized and visible to that account. If the Jira section says it is not configured, contact your application or Atlassian administrator; a Jira URL by itself does not connect the integration.

Optional integration

Connect GitHub and import a code change

GitHub import is useful when you want change-impact suggestions based on a pull request or branch comparison. The app does not clone your repository.

  1. Open Settings → GitHub repository.
  2. Enter the repository owner or organization, repository name, and base branch (usually main).
  3. Enter a GitHub personal access token with read access to repository contents and pull requests, then save the repository.
  4. Return to the workspace and enter your requirement and story context.
  5. Under Code diffs, choose From GitHub, enter a pull request number or a head branch/commit SHA, then choose Import diff into form.
  6. Review the imported diff and choose Get quality assistance.

The Paste option is available for supplying diff text in the workspace, but this deployment currently requires a saved GitHub repository and token before accepting non-empty diff content. If you only want requirement or story analysis, leave Code diffs blank.

To replace or remove the saved repository connection, return to Settings. The token is stored by the backend and is not displayed again after saving.

Step 3

Read, download, and continue results

  • Open the Results tab if it is not already selected. Responses are rendered with headings, lists, tables, and code formatting.
  • Use Markdown to save a portable Markdown copy or HTML to save a web page you can open or print.
  • Use the current result and its session context to ask for a refinement, such as prioritizing critical cases or adding negative tests.
  • Choose New session to clear the current session context and begin a separate request. This does not delete a previously downloaded file.
Results are generated guidance, not a record of tests executed by the application. Validate test cases, scripts, defects, and release recommendations before using them.

Account and connections

Manage settings and connections

Open the profile menu in the upper-right corner and select Settings. Depending on what your administrator has enabled, you may see:

  • Jira Cloud: connect, reconnect, or disconnect your Atlassian account.
  • Microsoft Entra ID: link the same-email company account to your app account so you can use Microsoft SSO at the next sign-in.
  • GitHub repository: save or update the repository, base branch, and token for diff imports, or remove that connection.

Settings show whether a connection is configured or linked. If an integration is not available, ask the application administrator whether its credentials, callback URL, and database setup are ready.

Ideas to try

Things you can do with the assistant

Design test cases

Provide acceptance criteria and ask for functional, negative, boundary, and accessibility checks.

Generate data ideas

Ask for representative, edge, invalid, and boundary values tied to specific test cases.

Review a pull request

Provide requirements plus a diff to identify affected areas and a focused regression scope.

Analyze a test run

Paste a test log or result summary in the requirement field and ask for failure triage and next steps.

Plan test automation

Describe the framework and application behavior, then ask for maintainable automation ideas.

Prepare a quality summary

Share verified test outcomes and known risks, then request a stakeholder-friendly summary.

The exact response depends on the information you provide and the AI model configured by your administrator. Ask one clear question at a time, and request a table or checklist if that format is easier to use.

Responsible use

Data, safety, and good practices

  • Do not enter passwords, access tokens, private keys, customer personal data, or other secrets in requirements, stories, diffs, or test logs.
  • Follow your organization’s rules for sharing Jira content, source code, and test data with the configured AI provider.
  • Connected integrations operate with the permissions of your authorized account; only connect accounts and repositories you are allowed to use.
  • Review generated test steps and scripts before running them. Check for inaccurate assumptions, missing security coverage, and unsafe commands.
  • Keep important results by downloading them; the workspace is designed for the current session and does not provide a searchable results archive.

Need help?

Troubleshooting

I cannot create an account or sign in.
Check your email and password. If your organization uses Microsoft SSO, try Sign in with Microsoft; an existing account may first need to be linked in Settings. Contact your app administrator if the option is missing.
The Jira or Microsoft connection option is missing or unavailable.
The administrator must configure the provider credentials, exact callback URL, and required database migration. Do not try to work around organization approval.
My Jira issue does not appear.
Reconnect the correct Atlassian account, refresh the issue list, and confirm the issue is assigned to that user and visible to them.
GitHub diff import fails.
Check the saved owner, repository, base branch, token permissions, and pull request number or head branch/SHA. Ask an administrator to verify network access if the issue continues.
The response is slow or an error appears.
Wait for the request to finish, check that the application services are available, then retry with a shorter input. If it persists, share the error text with your administrator without including secrets or sensitive work content.
The answer is incomplete or incorrect.
Add missing constraints or examples, ask a focused follow-up, and verify recommendations against your requirements and actual system.
