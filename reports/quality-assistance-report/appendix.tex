\section{Representative Request and Response Flow}
A representative request begins with an authenticated user entering one or more of the following: requirements, user stories, and a code diff. The frontend submits the context to the backend assistance route. The backend associates the request with the current user, saves it with a processing status, and builds an agent message. The agent service resolves a new or existing session, invokes the root agent, and gathers text from the agent events. The backend then stores the response and final status and returns the request and session identifiers to the frontend. A follow-up can send the session identifier to continue the agent interaction.

\section{Reproducibility Checklist for a Future Evaluation}
\begin{itemize}
  \item Record the application revision, model provider, model identifier, prompt revision, and runtime configuration.
  \item Preserve anonymized input artifacts and the expected reference cases used for scoring.
  \item Use the same task set and review rubric for each baseline and assistant condition.
  \item Record generation time separately from human editing and review time.
  \item Track accepted, edited, and rejected generated items, with reasons.
  \item Report both aggregate scores and failure cases; do not omit unsafe or misleading outputs.
  \item Obtain approval before using organizational requirements, source code, or defect records.
\end{itemize}
