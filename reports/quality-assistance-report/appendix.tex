\section{Representative Request and Response Flow}
A request usually starts after login. The user enters some mix of requirements, stories, and code differences. The frontend posts that to the backend assistance route. The backend attaches the current user, saves the request as processing, and builds an agent message. The agent service reuses a session if one exists, otherwise it opens a new one, calls the root agent, and collects text from the events. The backend stores the reply and the final status and returns the request and session ids. For a follow-up, the same session id goes back with the next turn.

\section{Reproducibility Checklist for a Future Evaluation}
\begin{itemize}
  \item Write down the application revision, model provider, model id, prompt revision, and runtime config.
  \item Keep anonymized inputs and the reference cases used for scoring.
  \item Use the same tasks and the same review rubric for every baseline and for the assistant.
  \item Time generation separately from editing and review.
  \item Track what was accepted, edited, or rejected, and why.
  \item Report the scores and the failures. Do not drop unsafe or misleading outputs.
  \item Get approval before using organisational requirements, source code, or defect records.
\end{itemize}
