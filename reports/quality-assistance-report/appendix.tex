\section{Representative Request and Response Flow}
A typical request starts with a signed-in user entering some mix of requirements, user stories, and a code diff. The frontend posts that context to the backend assistance route. The backend ties the request to the current user, saves it with a processing status, and builds an agent message. The agent service reuses an existing session or opens a new one, calls the root agent, and collects text from the agent events. The backend then stores the reply and the final status and returns the request and session identifiers. If the user wants to continue, the same session identifier goes back with the next turn.

\section{Reproducibility Checklist for a Future Evaluation}
\begin{itemize}
  \item Record the application revision, model provider, model identifier, prompt revision, and runtime configuration.
  \item Keep anonymized inputs and the reference cases that will be used for scoring.
  \item Use the same task set and the same review rubric for every baseline and assistant condition.
  \item Time generation separately from human editing and review.
  \item Track accepted, edited, and rejected items, and why.
  \item Report aggregate scores and the failures; do not drop unsafe or misleading outputs.
  \item Get approval before using organizational requirements, source code, or defect records.
\end{itemize}
