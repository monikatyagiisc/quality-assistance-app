\chapter{Conclusions}
\label{chap:conclusion}

The work resulted in a full-stack application that brings several STLC-related tasks into one workflow. Its React and TypeScript frontend, FastAPI and PostgreSQL backend, and Google ADK agent service are connected through a root agent that can route work to nine specialists. Their responsibilities range from test design and data suggestions to change-impact analysis, defect reporting, and release-readiness recommendations. The application also includes authentication, request persistence, Jira Cloud and GitHub context, optional Microsoft Entra SSO, and configurable model providers.

This implementation shows that these capabilities can be connected in a single application. Whether doing so improves coverage, reduces total quality-engineering effort, or helps find more defects has not yet been established by controlled evaluation. The agents provide suggestions for people to assess: execution analysis does not run a test suite, a script-healing recommendation does not change code, and a readiness assessment does not approve a release.

\section{Future Work}
The next phase should prioritize:
\begin{enumerate}
  \item introducing structured outputs and explicit validation between specialist stages;
  \item adding human approval and edit checkpoints for test cases and higher-impact recommendations;
  \item evaluating requirement-to-test traceability, correctness, review effort, latency, and cost against a documented baseline;
  \item testing with public projects and, after approval, anonymized organizational artifacts;
  \item investigating retrieval over approved requirements, test repositories, and historical defect data;
  \item integrating safely with CI/CD test execution and preserving durable, auditable session history; and
  \item conducting load, reliability, accessibility, privacy, and security reviews before broader deployment.
\end{enumerate}

The next question is not simply whether an LLM can produce a plausible testing artifact. It is whether an orchestrated assistant can produce useful, traceable work consistently, without adding more review effort than it saves. The prototype provides a basis for investigating that question, but the answer will depend on evaluation against a clear baseline.
