\chapter{Conclusions}
\label{chap:conclusion}

This project addressed the fragmentation of software quality activities by developing and evaluating an AI-driven Quality Assistance application for the Software Testing Life Cycle (STLC). The application combined a React and TypeScript frontend, a FastAPI backend, a PostgreSQL database, and a separate agent service implemented using Google’s Agent Development Kit (ADK).

At the centre of the application was a root agent responsible for interpreting user requests and coordinating nine specialised agents. These agents supported test-case generation, test-data generation, automation recommendations, test execution analysis, self-healing suggestions, change-impact analysis, defect reporting, test summary generation, and release-readiness assessment.

The application also incorporated user authentication, request persistence, Jira Cloud integration, GitHub integration, optional Microsoft Entra single sign-on, and configurable language-model providers. The human-in-the-loop refinement workflow allowed engineers to review generated responses, provide further instructions, and rerun requests using the existing session context.

The completed evaluation used 60 benchmark scenarios across six categories and compared manual testing, a single-LLM workflow, and the developed multi-agent application. Three experienced testers reviewed the generated artefacts using a five-point rating scale. The evaluation considered the quality of individual specialist outputs, orchestration performance, workflow completion, human correction requirements, response latency, operational cost, and end-to-end effort.

The results showed that the end-to-end workflow time decreased from approximately 40 working hours in the manual process to one hour using the multi-agent application. This represented a measured time reduction of 97.5\%. Active human effort decreased from approximately 30 hours to 35 minutes, including review and refinement activities.

At the specialist level, test-data generation achieved 97.2\% validity, test-case generation achieved 94.0\% requirement coverage, and test-summary reporting achieved 97.0\% factual accuracy. The orchestration layer achieved 96.0\% specialist-selection accuracy and a 94.0\% workflow completion rate.

These findings demonstrate that the developed application was able to coordinate multiple testing-related activities through a common interface and reduce the time required to prepare and review testing artefacts in the evaluated scenarios. The results also show that the multi-agent approach provided a structured alternative to handling each testing activity separately.

The application is intended to support quality engineers rather than replace their judgement. The execution-analysis agent works with supplied test evidence and does not independently execute external test suites. The self-healing agent provides recommendations without directly changing repository files. Similarly, the release-readiness agent provides supporting information, while the final release decision remains with the responsible engineering team.

Overall, the project demonstrated the practical feasibility of applying a specialised multi-agent architecture to software quality assistance. The evaluation provided measured evidence of workflow efficiency and specialist performance within the selected benchmark. Further work is required to improve validation between agents, strengthen session persistence, expand the evaluation dataset, and assess the application across a wider range of software projects and operational environments.

\section{Future Work}
The next steps I have identified, in order:
\begin{enumerate}
  \item Structured outputs and checks between specialist stages;
  \item An explicit approval step and editing of individual cases, building on the refine-and-rerun loop that already exists;
  \item An evaluation of traceability, correctness, review effort, latency, and cost against a baseline written down in advance;
  \item Trials on public projects and, after approval, on anonymized organisational artifacts;
  \item Retrieval over approved requirements, test repositories, and historical defects;
  \item A careful CI/CD hook for test execution, and session history that survives a restart and can be audited; and
  \item Load, reliability, accessibility, privacy, and security reviews before this is treated as a wider deployment.
\end{enumerate}
